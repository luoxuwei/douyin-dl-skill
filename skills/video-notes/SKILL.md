# video-notes · 视频变文档

脚本层和内容无关，五步固定；内容层按视频类型选一种整理方式。脚本都在 `${CLAUDE_SKILL_DIR}/../video-dl/scripts/`。

| 步 | 脚本 | 产物 |
| --- | --- | --- |
| 1 拿到视频 | `video-dl.mjs`（网络链接）；本地文件直接用 | `原始/<标题>.mp4` |
| 2 转写 | `transcribe.py`（transcribe skill） | `原始/<标题>.md .srt .txt .asr.json` |
| 3 抽帧 | `frames.mjs` | `帧/<标题>/NNNN.jpg` 和带秒数的 `sheet-*.jpg` |
| 4 整理 | 你按内容类型做，见下 | `图/*.jpg`，链接表，要点 |
| 5 成文 | 写 `<主题>.md`，`notes-pdf.mjs` 转 PDF | `<主题>.md`，`<主题>.pdf` |

工作目录：用户指定的输出目录，没指定就在当前目录建 `视频笔记-<日期>/`。

## 0. 开工前判断内容类型

看标题、文案、转写开头，把视频归到下面一类。拿不准就用 AskUserQuestion 问一次，同时问文档主题和关注点。多个视频问是合成一份还是各一份，默认合成一份、每个视频一章。

| 类型 | 典型视频 | 整理方式 | 抽帧找什么 | 要不要查链接 |
| --- | --- | --- | --- | --- |
| 课程 / 讲解 | 网课、公开课、知识科普、论文讲解 | 按讲解顺序分节，每节要点，关键定义和公式原话引用，末尾"一页复习"（术语表加自测问题） | 幻灯片、板书、公式、图表、代码 | 提到的论文、书、工具查 |
| 演讲 / 访谈 / 口播观点 | 演讲、播客、对谈、观点类口播 | 核心论点三到五条，每条配原话和时间戳；金句单列；有争议的地方标"讲者观点" | 讲者展示的图、数据页 | 提到的人、书、事件查 |
| 操作教程 | 软件教程、配置演示、实验操作 | 步骤清单，每步一句做什么加一句注意什么，配对应画面截图；前置条件和常见错误单列 | 每个关键操作的界面截图，命令行输出 | 用到的软件、仓库、文档查 |
| 资源推荐 / 书单 | 书单、课程推荐、工具推荐 | 一页总览表（资源、负责哪一段、作者的用法），每项一节：封面、作者出版社、链接、视频里的评价 | 封面、网站首页 | 每项都查，链接要核对 |
| 产品评测 / 开箱 | 硬件软件评测 | 参数表、优缺点表、结论；数据类断言引原话 | 产品外观、参数页、对比图 | 官网、购买页查 |
| 会议 / 组会录像 | 内部讨论 | 议题、决定、待办（谁、什么、何时），按发言人分段 | 共享屏幕的页面 | 一般不查 |
| 其他 | 上面都不像 | 全文转写加时间戳，前面加一段摘要和关键词，让用户自己再加工 | 用户指定 | 用户指定 |

一个视频混合几种（课程里推荐了书）就叠加：主体按课程，附一节资源表。

## 1. 拿到视频

- 网络链接：`node video-dl.mjs <链接> 原始/ --quality 720`。多个逐个跑。博主主页或合集链接走 video-dl 的批量流程，先列清单确认。
- 本地文件：不复制，记下路径。文件夹则处理里面所有视频。
- 记下每个视频的标题、时长（`ffmpeg -i`）、来源链接或路径。

## 2. 转写

`<venv python> transcribe.py <文件或原始/> --outdir 原始/ --lang zh --prompt "<标题、用户给的人名术语、课程大纲里的词>"`。转完抽查 md，同音字用 Edit 改；网络视频的文案（分享文本、标题、话题标签）和课程讲义是最好的校正依据，用户贴了就存成 `文案.md` 参考。

课程和演讲一小时以上：`--merge 40` 段落长一点；教程和口播 `--merge 20`。

## 3. 抽帧

`node frames.mjs 原始/<标题>.mp4 帧/<标题> --every N`。5 分钟以内 `--every 1`；半小时 `--every 3`；一小时以上 `--every 5`。幻灯片类视频画面变化少，`--every 5` 也够。

## 4. 整理

1. 用 Read 看每张 `sheet-*.jpg`，每格左上角是秒数。按上表"抽帧找什么"定目标，转写里"这张图""这本书""看这里"出现的时间是线索。
2. 定位到秒数后 Read 那一帧确认，`ffmpeg -i 帧/x/NNNN.jpg -vf crop=W:H:X:Y 图/<名>.jpg` 裁出。主播头像或字幕压住的，换相邻秒数或裁掉被压部分。幻灯片一般整帧留，只裁掉播放器边框。
3. 按上表"要不要查链接"，需要的起一个子代理查：名称、作者或作者方、官方页或 GitHub 优先，其次出版社页和豆瓣，每个链接访问确认对得上，中译本一并查。一次交给一个子代理。
4. 按类型提炼内容：要点、步骤、论点、参数，每条能回指转写的时间戳。不确定的问用户，不猜。

## 5. 成文

结构按类型套 `${CLAUDE_SKILL_DIR}/模板.md` 里对应的一节：

- 开头一段来源说明：视频、日期、转写方式、图片来源。
- 一页总览：类型决定形式，课程是要点列表，教程是步骤清单，书单是表，演讲是论点。
- 每个视频一章：先整理后的内容，再附语音转文字全文（带时间戳）。全文放后面，读者先看整理。
- 末尾按需：术语表、资料总表、待办表。

图片用相对路径 `图/x.jpg`。然后 `node notes-pdf.mjs <主题>.md --footer "<主题>"`。用 Read 看 PDF 前两页确认排版和图片都在。

## 6. 交付

告诉用户：PDF 路径和页数；判定的内容类型和为什么；每章一句话；转写里改过的错字；没找到画面或链接的项。

## 用中学：经验日志

`${CLAUDE_SKILL_DIR}/../video-dl/经验.md` 是三个 Skill 共用的踩坑记录。开工前读最近 20 条；某一步失败先搜里面有没有同样现象；用户对整理方式的反馈（比如"课程笔记要按讲解顺序不要按主题"）也算经验，解决完追加一条。内容类型对照表不够用时，在报告里提议加一类，用户同意后改 SKILL.md 和模板。

## 硬约束

- 转写和抽帧全在本地。视频归原作者，文档仅供个人学习，不二次分发视频文件。
- 链接必须核对过才写；查不到写"未找到"，不编。
- 整理的要点必须能回指转写时间戳；讲者观点标明是观点，不写成事实。
- 转写文字标"AI 生成可能有错"。
- 一次别处理超过十个视频，多了让用户分批。
